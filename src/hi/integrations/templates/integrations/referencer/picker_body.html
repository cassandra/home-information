{% load icons %} {% comment %} Picker modal body. The static structure of the picker: - Optional integration selector (when 2+ ATTRIBUTE_REFERENCE integrations are enabled). - Search form (POSTs to the search endpoint via attr-picker.js; the JS handles the async swap of the results container). - Selection chip row (the only HTML the JS module renders). - Results container (server-rendered partial swapped in on each search). - Attach form holding ``selections_json`` and the Add button. The JS serializes its in-memory selection set into the hidden input right before submit; the server then creates one TEXT attribute per record and returns antinode.refresh_response(). Per-search state and selection state are JS-owned. This template renders the surrounding scaffold and the initial empty state. DOM classes, data-attribute names, and wire-format field names come from ``hi.constants.DIVID`` (mirrored in ``static/js/main.js`` under ``Hi.ATTR_PICKER_*``) so templates / JS / view code all use the same strings.
